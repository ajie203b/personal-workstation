# 构建与发版

这份文档讲「怎么把它做出来、怎么发出去」。功能与用法看 [../README.md](../README.md)。

## 环境要求

| 依赖 | 位置 / 版本 |
| --- | --- |
| JDK 21 | `%LOCALAPPDATA%\jdk-21`（Capacitor 8 要求；构建时把 `JAVA_HOME` 指过去） |
| Android SDK | platform 35 + build-tools 35.0.0，装在 `%LOCALAPPDATA%\Android\Sdk`；路径写在 `android/local.properties`（已 gitignore） |
| 中文项目路径 | `android/gradle.properties` 里已加 `android.overridePathCheck=true`，否则 AGP 拒绝构建 |
| Android Studio 用户 | `Settings → Build, Execution, Deployment → Build Tools → Gradle → Gradle JDK` 选 JDK 21 |

`JAVA_HOME` 必须写成 Windows 反斜杠形式。Git Bash 习惯写的 `/c/Users/...` 会被 JDK 启动器当非法路径，Gradle 报的却是「找不到签名配置」一层的错，很难往回猜。

## 本地开发

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # vitest 单测：日期解析 / 自然语言录入 / 重复任务推算
npm run build      # 产出 dist/ + PWA（Service Worker 自动生成）
npm run preview    # 生产预览：http://localhost:4173
npm run preview:lan  # 局域网访问
```

## 发网页版

```bash
bash scripts/deploy-gh-pages.sh
```

脚本构建 `dist/` → 按 `package.json` 写 `version.json` → 只快进推送 `gh-pages`（远端分叉时停下报错，不覆盖历史）。只有纯文档/脚本改动、要复用已有 `dist/` 时才加 `--fast`；**代码改动时别用**，否则推上去的是旧产物。

`dist/` 只存在于 `gh-pages` 分支，main 不跟踪它（`.gitignore` 忽略 `dist`），所以构建产物的增删不会让 `git status` 变脏。

## 出 APK

```bash
npm run build            # 先构建 Web 资源
npx cap sync android     # 同步进安卓工程（web 资源变化后必须重新执行）
```

然后任选其一：

- **Android Studio**：打开 `android/` → `Build > Build App Bundle(s) / APK(s) > Build APK(s)`
- **命令行**：

  ```bash
  cd android
  ./gradlew assembleDebug      # app/build/outputs/apk/debug/app-debug.apk
  ./gradlew assembleRelease    # app/build/outputs/apk/release/app-release.apk（签名正式包）
  ```

## 完整发版链路（网页和手机都要生效，六步一步不能省）

「检查更新」有两个数据源：主源是 Pages 上的 `version.json`（静态文件带 CORS，网页版与安卓壳内都能读，不吃 API 限流），GitHub Releases API 只在确有新版时用来取 APK 直链。所以只推 main 不推 Pages，两端都还以为自己是最新；只推 Pages 不发 Release，手机能收到「发现新版本」却拿不到新包。

本仓库的约定：**每完成一个功能或修掉一个 bug，收尾就走这六步发一个新版本**——只提交代码不发版，等于改动没交付。

1. **升版本号**：`npm version <x.y.z> --no-git-tag-version`（一次改好 `package.json` 与 `package-lock.json`）；再手改 `android/app/build.gradle` 的 `versionCode`（**每发一版 +1**，Android 只认它判断能否覆盖安装）与 `versionName`（跟 npm 版本一致）。动手前先确认这一版不是空的：`git log --oneline origin/main..HEAD` 看有没有未发的提交，`gh api repos/ajie203b/personal-workstation/releases/latest --jq .tag_name` 对一下线上版本。
2. **提交并推送 main**：功能改动与版本号改动进同一个提交。
3. **发网页版**：见上一节。跑完自己核对一次 `curl -fsS https://ajie203b.github.io/personal-workstation/version.json`——Pages 重建有几十秒延迟，脚本末尾那次 curl 很可能仍打印旧值。
4. **出安卓包**：`cd android && JAVA_HOME="%LOCALAPPDATA%\jdk-21" ./gradlew assembleRelease`。
   - 增量构建约 20 秒，首次全量约 3.5 分钟。若 `gradlew` 报 `SocketTimeoutException: Connect timed out` 且栈顶是 `org.gradle.wrapper.Install.forceFetch`，那是 wrapper 在下 Gradle 发行版而不是项目坏了：本机 `GRADLE_USER_HOME=D:\gradle-home` 一旦被清空，就要重新下约 230MB 的 `gradle-8.11.1-all.zip`，而官方源只有约 250KB/s，撑不过 wrapper 写死的 10s 超时。处理办法是先把发行版预置进 `$GRADLE_USER_HOME/wrapper/dists/gradle-8.11.1-all/<hash>/gradle-8.11.1-all.zip`（删掉残留的 `.part` / `.lck`），国内镜像约 46MB/s，再**用官方 `gradle-8.11.1-all.zip.sha256` 校验一致**后重跑构建。别改仓库里的 `gradle-wrapper.properties`，也别反复重跑碰运气。
5. **验包**（构建成功不等于包是对的，三查缺一不可）：
   - `aapt2 dump badging app-release.apk | grep ^package` → versionCode / versionName 是新版；
   - `keytool -printcert -jarfile app-release.apk` 的 SHA256 指纹必须与上一版一致，不一致说明换了 keystore，已装设备只能卸载重装、数据会丢；
   - `unzip -p app-release.apk assets/public/assets/<本次改动的资源文件>` 确认改动真的进了包（对抗「sync 没生效 / 复用了旧 dist」这类静默失败）。

   然后复制成 `apk/personal-workstation-v<版本>.apk`，并更新本文档「本机当前产物」与 README 顶部版本行。
6. **发 Release**（手机更新提示的唯一来源）：

   ```bash
   gh release create v<x.y.z> apk/personal-workstation-v<x.y.z>.apk \
     --title "v<x.y.z> · <一句话>" --notes "<改动清单 + 在线版链接>"
   ```

   资产名带版本号，App 内按接口返回的 `browser_download_url` 取下载地址，不拼死路径。

**收尾核对**：`version.json` = 新 tag = Release 资产存在且能下载，三处一致才算发完。

## 每日模型排名数据

`.github/workflows/intelligence.yml` 每天 05:17 UTC 调 artificialanalysis.ai 的 `GET /api/v2/data/llms/models`，取智能指数前 30 生成 `public/intelligence.json`，有变化就提交到 main。

- 数据链路：`scripts/fetch-intelligence.mjs` 优先用官方 API（需要仓库 **Settings → Secrets and variables → Actions** 里的 `AA_API_KEY`）；**没有这个 secret 时自动退到解析官方公开榜单页**（`https://artificialanalysis.ai/leaderboards/models` 里的 RSC payload），所以不再出现「工作流天天失败、榜单永远不更新」。
   两条路都只取智能指数、都取前 30，失败一律不覆盖旧文件并以非 0 退出。
- 手工跑一次：`node scripts/fetch-intelligence.mjs`（本地无 key 也能出 `public/intelligence.json`），或 `gh workflow run intelligence.yml`。
- App 端（`src/lib/intelligence.ts`）每天最多静默拉一次：先试 `raw.githubusercontent.com/.../main/public/intelligence.json`，失败再试 Pages 上的同名文件；都失败就保留缓存。手动刷新时只有真从远端取到新数据才提示「已更新」。
- 卡片展示的是**官方图表原图** `public/intelligence/chart.png`（来自 artificialanalysis.ai 的图表导出/截图），代码不再自绘柱状图；图下方的「榜首 + 数据日期」由上面那份 JSON 提供。官方没有公开的"图表图片"接口，所以这张原图随版本更新，不随每日数据变化；想更新它，替换这个文件即可。
- 想立即更新：在卡片右上角点刷新（会强制拉一次）。

## 签名密钥与口令

- keystore：`android/app/workstation.keystore`，口令写在**本机** `android/keystore.properties`。两个文件都已 gitignore，`build.gradle` 运行时读取，缺文件直接报错而不是回退到明文。
- **换手机重装、后续升级都用同一个 keystore 签名**，否则需要先卸载旧版（会丢数据，记得先在设置里导出备份）。装 debug 包后再装 release 包报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` 也是同一原因。
- ⚠️ 这个仓库曾长期私有，现已公开，而 git 历史里带着旧签名口令。请把它当**已泄露**处理：要真正收紧就得生成新 keystore，并让已安装设备卸载重装（同签名覆盖升级会失效）。口令不再出现在当前代码里，但历史不改写。
- 换电脑构建前请先备份这两个文件——丢失后无法对已安装设备覆盖升级。
