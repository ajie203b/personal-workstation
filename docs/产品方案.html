01市场调研摘要

10 款一体化竞品 + 7 款任务管理产品 + 6 类文档/AI 面板专项深挖的核心结论。

1.1 竞品格局：五类玩家，各自所长

流派代表对本项目最有价值的启示
全能工作台Notion、Microsoft Loop「任务=数据库行=页面」同源架构；Loop 的可移植组件跨模块同步 来源

1.2 三大趋势（2024–2026）

🤖 AI 内置化

Notion Business 2025-05 起 AI 无限内置；Tana/Capacities/Craft 均原生集成。AI 面板不是附加件，应作为一级模块设计。

🔗 任务与笔记同源

Capacities「任务强绑定笔记」、Obsidian Tasks、Tana Supertag——三模块数据同源是业界收敛方向，互跳应从数据层打通。

📐 三栏布局收敛

左侧导航 + 中央画布 + 右侧信息/反链面板成为事实标准（Notion/Obsidian/思源/Reader 一致）。

1.3 最值得借鉴的模式 Top 6

  • Things 3 四清单时间语义（Today / Upcoming / Anytime / Someday + Logbook 归档）——最简洁的「每日/每周/长期」分层，直接采用 来源
  • Readwise Reader 双坐标位置记忆——「最近滚动位置」与「深度阅读进度」分开记录、双色进度条渲染，防快速翻页污染 来源
  • Heptabase/Reader 注释即锚点——高亮自动生成深链，任务可直跳「文档某一句话」 来源
  • Poe/OpenRouter 额度范式——订阅档位↔点数余额进度条+重置日；运行中任务卡片（徽标+脉冲+token 实时数+Stop） 来源
  • TickTick 同数据四视图（列表/看板/日历/四象限一键切换）+ 内置番茄钟/习惯 来源
  • 全局 Cmd+K 命令面板——Notion/Craft/Tana/Akiflow 一致采用，是三模块互跳的最高效入口 来源
⚠️ 风险提示：Omnivore 已于 2024-11 关停、Pocket 已宣布关停——Reader 类「位置全端同步」已成标配能力，自建工作台必须内建而非外挂。（来源1 · 来源2）

03完整技术路线

选型原则：本地优先、单人开发可持续维护、React 生态组件复用最大化、桌面/双端就绪。

3.1 技术栈选型及理由

层选型理由与对比结论
前端框架React 18 + TypeScript + Vite 首选关键组件（react-pdf / react-markdown / dnd-kit / FullCalendar）全部是 React 一等公民；个人工具无 SSR/SEO 诉求，Vite 比 Next.js 更轻。Vue/Svelte 备选可走通但组件生态需妥协（详见 5A5B 素材对比表）
桌面壳Tauri 2（可选，后期）增强Rust 壳，安装包 ~10MB、内存显著低于 Electron；PWA 先行，需要系统级能力时再包壳 tauri.app
UI 组件Tailwind CSS + shadcn/ui + Radix无头组件 + 完全可定制 Token，最贴合「MD3 骨架 + HIG 气质」的融合设计
状态管理Zustand（全局）+ TanStack Query（异步）跨模块共享状态的最小方案；Store 按四域拆分（见 4.4）zustand.docs.pmnd.rs
路由React Router v7路由分区承载模块互跳上下文（见 4.3）
本地存储IndexedDB（Dexie.js 封装）结构化大容量（PDF Blob、批注、任务、会话）；LocalStorage 仅存 UI 偏好 dexie.org
同步/协作（预留）Yjs CRDT + y-indexeddb + y-websocket（自托管）今天单机，明天多端/协作无需重构；冲突自动合并 yjs（22.9k★，2026-09 活跃）
图表ECharts（按需引入）或轻量 SVG 自绘AI 用量仪表盘四指标下钻图表

3.2 整体架构（单体组件化，明确不上微前端）

// 架构分层 —— 个人工作台（单 SPA） ┌─────────────────────────────────────────────────────────┐ │ UI 层 TodayDashboard │ Tasks │ Docs │ AIPanel │ ⌘K │ ├─────────────────────────────────────────────────────────┤ │ 状态层 Zustand(任务/文档/AI/UI 四域 Store) + 事件总线 │ ├─────────────────────────────────────────────────────────┤ │ 领域层 任务引擎 │ 文档引擎(PDF/MD) │ AI 网关(Provider池) │ ├─────────────────────────────────────────────────────────┤ │ 数据层 Dexie/IndexedDB(文件·批注·任务·会话) + Yjs 模型 │ ├─────────────────────────────────────────────────────────┤ │ 同步层 y-indexeddb(本地) → y-websocket(可选) → 导出备份 │ └─────────────────────────────────────────────────────────┘
为什么不上微前端/模块联邦：微前端解决「多团队独立部署/异构栈」问题，本项目三大模块需要深度数据联动（互跳矩阵 2.5），单体组件化 + 路由分区 + 共享 Store 成本最低、体验最好。模块联邦仅在未来把 AI 面板拆为独立服务时再评估。（5A5B 调研结论 B2）

3.3 数据存储与同步方案

数据存储形态要点
PDF 原文件IndexedDB Blob按文件 hash 去重；阅读位置以 hash 为主键（文件重命名不丢进度）
阅读位置{docHash, page, offset, progress, updatedAt}双坐标：lastScroll 与 readingProgress 分开存；MD 存块锚点而非像素偏移，内容增删后仍准确 依据
批注{id, docHash, page, text, color, comment, deepLink}结构化存储，天然可供 AI 摘要 / 任务生成消费
任务{id, title, tier, priority, docRef?, aiRef?, doneAt}docRef/aiRef 即互跳外键；完成入 Logbook
AI 配置Provider 卡片 + Key 槽位（本地加密）永不上云明文；用量记录 {ts, provider, model, tokens, cost, module}
跨端同步（预留）Yjs Doc + y-websocket先 y-indexeddb 本地持久化，同步上线零迁移；纯文件走 WebDAV

⌘K 面板 + 今日 Dashboard + 批注转任务 / AI 划词问答 + 深色模式 + 动效细化 + Tauri 包壳（可选）。验收：互跳矩阵 6 条链路全通。

Store职责（⭐=跨模块共享项）

跨模块动作型联动（如「批注→转任务」）不直接调用对方 Store，统一走声明式深链工具，保持模块单向依赖：

// 互跳统一入口 shared/DeepLink.ts —— 模块间零直接 import import { openTask, openDoc, openAi } from '@/shared/DeepLink'; openDoc({ docHash, page: 42, hl: annId }); // 任务 → 文档定位 openTask({ preset: { title: 摘录, docRef } }); // 批注 → 转任务 openAi({ context: { task: taskId } }); // 任务 → AI 会话
互跳机制小结：① 路由参数承载定位上下文（可分享/可回退）；② Zustand 共享选中态；③ DeepLink 工具收敛跳转动作，任何模块只依赖它而非彼此——与竞品「任务=行=页面」同源思想一致，实现更轻。

05美术方案（MD3 × HIG × 极简）

总纲：用 MD3 的系统化 Token 当骨架，用 HIG 的克制气质定调性——信息密度疏朗、色彩留白做层级、动效轻而有目的。两体系要点各 ≤10 条的完整摘要见 5A5B 素材报告。

5.1 设计原则（三条）

层次靠留白优先用间距与 surface 色阶分层，阴影只用于悬浮态（HIG 材质哲学）
一屏一事每个视图单一主任务，次级信息进右栏/抽屉（极简主义）
Token 驱动30 个语义变量亮暗两套，全站零硬编码色值（MD3 方法论）
