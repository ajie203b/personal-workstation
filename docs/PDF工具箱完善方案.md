# PDF 工具箱完善

## 目标和范围

保持文件与密码在设备本地处理，完成现有 PDF 工具箱承诺的功能与输入、处理、导出闭环。以桌面浏览器、PWA、安卓 WebView 为目标，兼容现有下载和文档库入口。

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| pdf-engine | qpdf WebAssembly、独立 Worker、取消与错误分类 | 无 |
| pdf-input | 校验 PDF、已知密码打开、清理密码 | pdf-engine |
| pdf-compress | 无损/均衡/更小体积、前后对比、结果不增大 | pdf-engine、pdf-input |
| pdf-security | AES-256 加密、密码确认、打印复制权限、已知密码解密 | pdf-engine |
| pdf-organize | 页面拖动排序、批量删除旋转、选页导出 | pdf-input |
| pdf-output | 结果下载/入库、ZIP 正确禁用入库、进度与取消 | 各处理模块 |

顺序：引擎 → 加密/压缩 → 通用输入与导出 → 页面及其他现有面板 → 集成验证。

## 开源参考与技术选择

- BentoPDF：参考本地处理、密码工具分离与功能分组的流程；不复制其 AGPL 代码。https://github.com/alam00000/bentopdf
- qpdf-wasm 0.3.0：ISC 包装层、无运行时依赖、内置 qpdf 12.2.0；WASM 随应用打包，不从 CDN 动态加载。https://github.com/neslinesli93/qpdf-wasm
- qpdf：Apache-2.0，引擎加密、压缩、错误码和权限按 12.2 文档实现。https://qpdf.readthedocs.io/en/12.2/cli.html
- 延续 React 18、TypeScript、pdf-lib、pdf.js、dnd-kit 与项目现有 UI。qpdf 专注结构压缩与图片重编码，保留文本/矢量内容，不把整份 PDF 栅格化冒充压缩。

## 验收条件

- 移除压缩、加解密的“即将支持”占位；提供真实可操作入口。
- 压缩支持无损、均衡与更小体积；显示前后大小与节省比例；无收益返回原文档并明确说明。取消可立即终止 Worker。
- 加密采用 AES-256，密码不能空、必须二次确认，支持中文和特殊字符；解密遇错误密码不输出文件。密码不进入日志、本地存储、文档库元数据。
- 现有合并、拆分、页面编辑、签名、水印和转图片能打开带已知密码的文件；损坏、伪扩展名及空文件有明确反馈，不忽略加密导出错误结果。
- 页面排序、删除、旋转在导出中生效，不能删光所有页；支持反选/奇偶页与恢复。
- PDF 转图支持页码范围、质量、进度与取消。ZIP/图片结果不显示可用的“进文档库”，PDF 输出可以下载或入库。
- 页面不会在处理时因切换文件混用旧结果；Worker 及 pdf.js 文档、Canvas 和临时 URL 在结束/卸载时释放。
- 为引擎写真实 PDF 回归测试（页面、文本、表单、密码、压缩）；浏览器中验证实际渲染、下载、取消、窄屏和离线资源。

## 代码与验证

源码、测试放在 `src/modules/tools/pdf/`，遵循现有命名、单引号和纯逻辑/界面分离模式。新增依赖固定版本、禁用安装脚本并记录许可证；不改用户已有未提交工作，不上传文件，不实现未知密码破解。

命令：`npm test -- src/modules/tools/pdf`、`npm test`、`npm run build`、`npx cap sync android`、`android/gradlew.bat --offline assembleRelease`。
